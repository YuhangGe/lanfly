# lanfly

> 把消息和文件，直接送到同一局域网的设备上。

`lanfly` 是一个轻量的局域网聊天和文件传送工具。两台设备运行同一条命令，就能自动发现彼此，开始聊天或拖拽文件，不需要账号、云服务或中心服务器。

![lanfly 界面](docs/lanfly.png)

## 为什么用 lanfly

- **打开就能用**：没有注册、没有配置，浏览器就是界面。
- **自动发现**：同一 Wi-Fi / 局域网内的设备会自动出现。
- **聊天和文件一起**：文字、图片、压缩包、任意文件都可以直接发。
- **手机也能加入**：打开主机的局域网网页，以独立设备身份聊天、上传和下载文件。
- **共享键鼠**：两台单屏 Mac 可共享一套键盘和鼠标，在网页中配置。
- **Room ID 组网**：主机使用相同 Room ID 加入同一组，手机打开网页即可接入。
- **不登录、不上云**：消息和文件只在本机与对方设备之间传输。
- **关掉即走**：不保存聊天记录，不留下账号，不依赖数据库。

适合在办公室、家里、工作室里快速传文件，或者和旁边的电脑说句话。

## 三步开始

1. 在第一台主机运行：

   ```sh
   npx lanfly
   ```

2. 首次启动会生成并保存六位 Room ID，后续读取保存值，终端会显示当前 Room ID，并自动打开 `http://127.0.0.1:8087`。另一台主机运行 `npx lanfly <显示的 Room ID>` 加入同一组。
3. 在左侧设备列表里选择对方，开始聊天；也可以直接把文件拖进聊天窗口。

要求：Node.js 22 或更高版本；两台设备在同一个局域网内。

### 常用选项

| 参数            | 作用                                        |
| --------------- | ------------------------------------------- |
| `--name <名称>` | 设置别人看到的设备名，默认是本机 hostname   |
| `--port <端口>` | 指定本地端口，默认 `8087`，被占用时自动顺延 |
| `--out <目录>`  | 接收文件的保存目录，默认系统下载目录        |
| `--no-open`     | 启动后不自动打开浏览器                      |

```sh
# 给设备起个容易认的名字
npx lanfly --name "客厅 Mac"

# 两台主机使用相同 Room ID
npx lanfly 123456

# 指定接收目录
npx lanfly --out ~/Downloads/lanfly
```

命令格式为 `npx lanfly [ROOM ID] [选项]`。Room ID 可使用 1–64 位字母、数字、下划线或短横线；省略时优先读取 `data.json` 中的 `roomId`，首次没有配置时随机生成六位数字并保存；显式指定时覆盖保存值。启动时会显示当前 Room ID。

## 发现设备

同一局域网内的 lanfly 会自动广播自己，通常几秒内就能在左侧看到对方。

如果网络禁用了组播，或者设备没有自动出现：

1. 点击右上角的 **添加设备**。
2. 输入对方的 IP，例如 `192.168.1.23`；端口不是 8087 时写成 `192.168.1.23:8088`。
3. 双方 Room ID 一致后，就会出现在列表里。

设备离线后会先显示为灰色；手动添加的设备会保留在列表里，方便重新连接。

## 手机与浏览器设备

在手机或另一台电脑的浏览器打开终端打印的局域网地址，例如 `http://192.168.1.10:8087`，即可作为独立设备接入，无需安装 Node.js。浏览器直接加入访问主机所在的组，不需要密码或 Room ID。

- 浏览器默认命名为 Android / iOS 等浏览器可识别的平台；点击左侧自己的名称可修改。相同浏览器、相同访问地址会记住身份，刷新或重新打开仍是同一设备。
- 两台 lanfly 主机 A、B 直连后，双方主机及其浏览器设备之间都能互发消息和文件。只交换本机接入的浏览器列表，不会把 B 连接的第三台主机 C 或 C 的浏览器继续转告给 A。
- 发给浏览器时先发送有效 **30 分钟** 的下载邀请。接收方点击后，发送页面才读取选中的文件并上传，主机边接收边转发下载，不在中间主机缓存文件。发送页面保持在线时可以重复下载，每次都会重新上传；发给主机的文件仍流式保存到下载目录。
- 发送文件后请保持发送页面打开；刷新、关闭页面会丢失所选文件，手机切后台或锁屏也可能暂停传输。关闭网页或连接中断后可能离线，不提供离线投递。不同浏览器设备的聊天和文件互相独立。
- `localhost` / `127.0.0.1` 打开的界面代表主机本身；通过局域网地址打开的界面代表浏览器设备，只提供聊天和文件功能，不操作主机设置或键鼠共享。

## 发送文件

- 拖拽文件到聊天窗口；
- 或点击输入框左侧的回形针；
- 或直接粘贴截图。

发给主机时，文件从发送浏览器流式上传，经主机转发后直接写入接收主机的下载目录；发给浏览器时由接收方点击下载触发同样的流式传输，中间主机不落盘。重名时自动命名为 `文件 (1).ext`、`文件 (2).ext`，不会覆盖原文件。

支持多选、进度显示和取消传输。接收端默认自动接收，所以请只在可信网络中运行。

## Room ID

主机通过 Room ID 隔离不同组网。UDP 发现、手动连接、消息、文件和键鼠连接均要求主机的 Room ID 相同；没有公开房间模式。手机通过 IP 打开网页时直接加入该主机所在的组。

发现公告、消息、文件和键鼠事件均以明文传输。Room ID 只是分组标识，不是密码或加密密钥。

## 共享鼠标键盘（macOS）

首版支持 macOS 12 或以上的 Apple Silicon / Intel Mac，一台服务端控制一台客户端，双方各一个活动显示器。Windows、Linux 的键鼠共享暂不支持，原有聊天和文件传输不受影响。不需要安装 Deskflow、Rust 或编译工具；正式发布的 npm 包按系统架构安装预编译原生模块。

1. 两台主机使用相同 Room ID 启动，在本机 WebUI 打开“键鼠共享”。
2. 双方分别授予运行 lanfly 的终端或 Node 进程 **辅助功能** 和 **输入监控** 权限。授权后点击“刷新权限”，无需重启。
3. 任意一方选择设备、本机角色和客户端位置，再点击“连接”。本机选“服务端”时对方自动成为受控客户端；本机选“客户端”时对方自动成为提供键鼠的服务端。不需要配对、校验码或对端网页确认。

一次只连接一台设备，已有连接的设备不会被其它连接接管。鼠标移出所选边缘后切换到客户端，移回相邻边缘返回服务端。支持键盘、鼠标按钮、滚轮和触控板滚动；不包含剪贴板、文件跨屏拖拽或多指手势。

任一端按 **Ctrl + Option + Command + Esc** 或点击“停止共享”，双方都会停止并关闭自动恢复。正常断网后，双方会重试连接；关闭终端后双方会释放按键和鼠标。

角色、位置、对端地址、Room ID 和自动恢复开关保存在 **`cli.js` 所在目录的 `data.json`**，开发构建对应 `dist/data.json`，与 shell 工作目录无关。后续直接启动会沿用保存的 Room ID，可按任意顺序自动恢复连接；显式指定其它 Room ID 会切换并保存新组，不会恢复旧组的连接。旧版本配对配置仅迁移角色和位置，需要在新房间里连接一次。

配置使用 `input` 分组保存键鼠连接，`browser` 分组保存浏览器会话的签名密钥，不保存聊天或键盘内容。可通过 `LANFLY_CONFIG_DIR` 指定配置目录。

重新构建会保留 `data.json`，它不会提交到 Git 或包含在 npm 发布包中。

## 远程桌面（macOS）

首版支持 macOS 12.3 或以上：一台被控 Mac 共享屏幕，控制端可以是另一台 lanfly 主机，也可以是打开主机局域网地址的浏览器或手机。视频通过 WebRTC 在两端直连，不经过 Node.js 中转，也不依赖云服务、STUN、TURN 或独立媒体服务器。

1. 两台主机使用相同 Room ID 启动；控制端在设备详情或右上角点击 **远程桌面**。
2. 被控 Mac 需要在“系统设置 → 隐私与安全性 → 屏幕录制”中授权运行 lanfly 的终端或 Node 进程，并在 **辅助功能** 中授权，以便接收远程鼠标键盘事件。
3. 控制端选择设备、画质，然后点击 **请求远程桌面**。
4. 被控端**不需要点击接受**：请求会按现有 Room ID 和设备身份校验后自动接受。被控端本机 WebUI 会打开一个被动的共享状态窗口，显示是谁在查看，并提供“停止远程桌面”按钮。
5. 控制端浏览器自动通过 `RTCPeerConnection` 接收 H.264 视频并绑定到 `HTMLVideoElement`，支持画面自适应和全屏。鼠标键盘控制会随远程桌面一起自动开启，不提供单独的仅查看模式。停止按钮会同时释放视频流、PeerConnection、数据通道和按键状态。

实现链路：macOS `ScreenCaptureKit` 持续采集主显示器 → `VideoToolbox` 硬件 H.264（Constrained Baseline，默认 30 FPS、4 Mbps、最高 1080p）→ Rust `webrtc-rs` 发送 RTP。SDP 和 ICE 只通过 lanfly 现有 Node.js 信令与设备身份通道转发；编码帧不会进入 JavaScript。远程键鼠事件通过已授权的 WebRTC DataChannel（DTLS 加密）直接发送到被控 Mac，由现有 Rust + Quartz 注入，不经过 Node.js 转发。

远程桌面会话使用唯一 `sessionId`，并绑定发起设备身份、目标设备和一次性令牌；SDP、ICE、停止和输入消息都会校验来源设备和令牌。远程桌面会自动开启键鼠控制，并在连接时停止现有键鼠共享，避免两套输入状态冲突。一次只允许一个远程桌面会话，只采集主显示器；不包含音频、剪贴板同步或文件跨屏拖拽。首版只使用局域网 host ICE candidate，不支持跨 NAT、VLAN 或公网。

从源码开发时需要运行 `pnpm build:native` 重新编译包含桌面模块的原生文件；正式发布包需按 macOS 架构包含带桌面模块的预编译 `lanfly-input-darwin-*`。

## 安全提醒

lanfly 面向可信局域网，类似 LocalSend，不是公网通信工具。

- **聊天和文件内容是 HTTP 明文**，同一网段内能抓包的人可以看到。不要在不可信 Wi-Fi 上传送敏感信息。
- **Room ID 不是访问密码**，会以明文传输；能访问主机网页的人可以直接以浏览器设备加入。
- **远程桌面会自动接受同一 Room ID 内已发现设备的请求**，并同时开启鼠标键盘控制；不会弹出接受确认。只应在完全可信的局域网使用，并在不需要共享时点击被控端的“停止远程桌面”。WebRTC/DTLS-SRTP 只保护媒体与控制传输，不替代身份授权。
- **不支持跨 NAT、跨 VLAN、VPN 或公网**，只适用于同一局域网。
- 不支持离线消息、断点续传、文件夹传输或历史记录；关闭终端后，本次会话的设备、消息和传输记录都会清空，主机下载目录中的文件会保留，浏览器下载邀请会失效。

## 常见问题

**看不到另一台设备？**

确认两台设备在同一网段，并允许防火墙接收 UDP `53318` 和 TCP `8087`（或实际顺延端口）。如果网络禁用了组播，用右上角的“添加设备”手动输入 IP。

**端口被占用怎么办？**

默认会从 `8087` 开始自动顺延，终端会打印实际地址。也可以用 `--port` 指定。

**文件保存在哪里？**

默认是 `~/Downloads`；Windows 是 `%USERPROFILE%\Downloads`。如果系统把下载目录重定向到 OneDrive，请用 `--out` 指定实际目录。

**重启后聊天记录还在吗？**

不在。lanfly 只使用内存保存本次运行的状态，关闭终端即清空；主机下载目录中的文件不受影响，浏览器下载邀请会失效。

## 开发

```sh
pnpm install    # 同时安装本地 Bun
pnpm build:native # macOS 开发：编译 Rust 原生组件（需 Rust 工具链）
pnpm dev        # Vite 8080 + 本地服务 8087
pnpm build      # 构建 dist/cli.js 和 dist/public
pnpm start      # 运行构建产物
pnpm test       # 单元 + 双实例集成测试
```

构建和开发脚本是 TypeScript，由 Bun 执行；发布到 npm 的 `lanfly` 包仍使用 Node 运行。更多实现细节可以直接看 `packages/`。

键鼠和远程桌面实现位于 `native/`（Rust/Neon/Quartz/ScreenCaptureKit/VideoToolbox/webrtc-rs）和 `packages/server/src/input/`、`packages/server/src/desktop/`。本地开发先运行 `pnpm build:native` 构建包含桌面模块的 `native/index.node`；正式包使用 `lanfly-input-darwin-arm64` / `lanfly-input-darwin-x64` 可选依赖。`pnpm build` 仅构建 JS 和 WebUI，不要求在其他系统上编译 Rust。

服务端通过 HID 层事件拦截和后台光标控制锁定本机鼠标。macOS 后台光标控制需要动态解析 WindowServer 的非公开接口；系统不提供该接口或锁定失败时，会停止共享并在 WebUI 提示，不会继续同时移动两端光标。

GitHub Actions 对两个 macOS 架构编译、检查并测试原生模块；JS/WebUI 检查通过后，发布事件依次发布两个原生包和主包。需为三个包配置 npm trusted publishing。发布新版本前运行 `npm version patch`（或指定版本），版本钩子会同步平台包、Cargo 和锁文件中的版本。当前仓库版本若已经发布，需先递增版本再发布包含此功能的新版本。

`pnpm test` 包含使用模拟原生层的双端明文连接和角色协商测试，不会监听或注入真实键鼠；`cargo test --manifest-path native/Cargo.toml --locked` 检查原生边界逻辑。真实设备验收仍需两台已授权的单屏 Mac，覆盖四个方向切换、修饰键与鼠标释放、滚动、断网、紧急停止及显示器热插拔。
