# lanfly

> 把消息和文件，直接送到同一局域网的设备上。

`lanfly` 是一个轻量的局域网聊天和文件传送工具。两台设备运行同一条命令，就能自动发现彼此，开始聊天或拖拽文件，不需要账号、云服务或中心服务器。

![lanfly 界面](docs/lanfly.png)

## 为什么用 lanfly

- **打开就能用**：没有注册、没有配置，浏览器就是界面。
- **自动发现**：同一 Wi-Fi / 局域网内的设备会自动出现。
- **聊天和文件一起**：文字、图片、压缩包、任意文件都可以直接发。
- **共享键鼠**：两台单屏 Mac 可共享一套键盘和鼠标，在网页中配置。
- **可选密码房间**：设置相同密码的设备才能互相发现。
- **不登录、不上云**：消息和文件只在本机与对方设备之间传输。
- **关掉即走**：不保存聊天记录，不留下账号，不依赖数据库。

适合在办公室、家里、工作室里快速传文件，或者和旁边的电脑说句话。

## 三步开始

1. 在两台设备上分别运行：

   ```sh
   npx lanfly
   ```

2. 终端会启动本地服务并自动打开浏览器。默认地址是 `http://127.0.0.1:8087`。
3. 在左侧设备列表里选择对方，开始聊天；也可以直接把文件拖进聊天窗口。

要求：Node.js 22 或更高版本；两台设备在同一个局域网内。

### 常用选项

| 参数              | 作用                                        |
| ----------------- | ------------------------------------------- |
| `--name <名称>`   | 设置别人看到的设备名，默认是本机 hostname   |
| `--secret <密码>` | 开启密码房间，只有相同密码的设备能互相发现  |
| `--port <端口>`   | 指定本地端口，默认 `8087`，被占用时自动顺延 |
| `--out <目录>`    | 接收文件的保存目录，默认系统下载目录        |
| `--no-open`       | 启动后不自动打开浏览器                      |

```sh
# 给设备起个容易认的名字
npx lanfly --name "客厅 Mac"

# 两台设备使用相同密码
npx lanfly --secret "my-lan-password"

# 指定接收目录
npx lanfly --out ~/Downloads/lanfly
```

密码也可以通过 `LANFLY_SECRET` 环境变量传入，避免出现在 shell 历史里。

## 发现设备

同一局域网内的 lanfly 会自动广播自己，通常几秒内就能在左侧看到对方。

如果网络禁用了组播，或者设备没有自动出现：

1. 点击右上角的 **添加设备**。
2. 输入对方的 IP，例如 `192.168.1.23`；端口不是 8087 时写成 `192.168.1.23:8088`。
3. 对方确认密码房间一致后，就会出现在列表里。

设备离线后会先显示为灰色；手动添加的设备会保留在列表里，方便重新连接。

## 发送文件

- 拖拽文件到聊天窗口；
- 或点击输入框左侧的回形针；
- 或直接粘贴截图。

文件会直接传到对方设备，自动保存到对方的下载目录。重名时自动命名为 `文件 (1).ext`、`文件 (2).ext`，不会覆盖原文件。

支持多选、进度显示和取消传输。接收端默认自动接收，所以请只在可信网络中运行，或使用 `--secret`。

## 密码房间

不设置密码时，局域网内所有公开设备都能看到你。

设置 `--secret` 后：

- 只有密码完全一致（区分大小写和空格）的设备能互相发现；
- 公开设备和密码设备互相不可见；
- 密码不会出现在发现公告里。

密码只负责“能不能发现和连接”，不负责加密聊天内容。见下面的安全说明。

## 共享鼠标键盘（macOS）

首版支持 macOS 12 或以上的 Apple Silicon / Intel Mac，一台服务端控制一台客户端，双方各一个活动显示器。Windows、Linux 的键鼠共享暂不支持，原有聊天和文件传输不受影响。不需要安装 Deskflow、Rust 或编译工具；正式发布的 npm 包按系统架构安装预编译原生模块。

1. 两台 Mac 均运行 `npx lanfly`，点击右上角 **键鼠共享**。
2. 按网页提示，在 macOS **系统设置 → 隐私与安全性** 中授予运行 lanfly 的终端或 Node 进程 **辅助功能** 和 **输入监控** 权限；授权后若检测未更新，请重启 lanfly。
3. 提供键鼠的一端选择 **服务端**，设置另一台 Mac 相对本机的上下左右位置，点击 **保存并启用**。
4. 另一端选择 **客户端**，从设备列表选择服务端，点击 **保存并启用**。设备未出现时，先用原有“添加设备”功能输入服务端 IP。
5. 对照两端 WebUI 显示的 8 位校验码，完全一致后在两端分别确认。首次配对窗口有效期为 2 分钟；过期后可在服务端重新允许配对。

鼠标移出所选边缘后，键鼠切换到客户端；从客户端相邻边缘移回即可回到服务端。按住键盘按键、修饰键或鼠标拖拽时不会切屏。支持键盘、鼠标按钮、滚轮和触控板滚动；不包含剪贴板、文件跨屏拖拽、触控板多指手势或登录/锁屏界面控制。

在任一端按 **Ctrl + Option + Command + Esc** 可紧急停止当前连接。网络断开、显示器数量变化或处理超时时会释放远端按键并恢复本机鼠标；紧急停止的一端不会自动重连。正常网络中断时，仍启用的客户端会尝试重新连接已配对服务端。

键鼠使用独立的 X25519 / AES-256-GCM 加密连接，并固定已确认的设备身份。校验码不一致时请停止共享。聊天房间密码不替代键鼠配对；键鼠配对也不会改变原有消息与文件的明文传输方式。

配对身份、角色和位置保存于 `~/Library/Application Support/lanfly/input.json`，不保存输入内容。可通过 `LANFLY_CONFIG_DIR` 指定配置目录；两台设备的配置文件不要互相复制。关闭网页继续共享，退出进程停止；重启进程后需在 WebUI 手动启用。更换控制对象前，请先解除旧配对。原生组件加载失败或权限不足时，聊天与文件传输仍然可用。

## 安全提醒

lanfly 面向可信局域网，类似 LocalSend，不是公网通信工具。

- **聊天和文件内容是 HTTP 明文**，同一网段内能抓包的人可以看到。不要在不可信 Wi-Fi 上传送敏感信息。
- **公开房间没有访问控制**，任何能访问端口的人都可以发消息或投递文件；接收端会自动保存。
- **密码需要足够强**，弱密码仍可能被离线猜测。
- **不支持跨 NAT、跨 VLAN、VPN 或公网**，只适用于同一局域网。
- 不支持离线消息、断点续传、文件夹传输或历史记录；关闭终端后，本次会话的设备、消息和传输记录都会清空，已接收的文件会保留。

## 常见问题

**看不到另一台设备？**

确认两台设备在同一网段，并允许防火墙接收 UDP `53318` 和 TCP `8087`（或实际顺延端口）。如果网络禁用了组播，用右上角的“添加设备”手动输入 IP。

**端口被占用怎么办？**

默认会从 `8087` 开始自动顺延，终端会打印实际地址。也可以用 `--port` 指定。

**文件保存在哪里？**

默认是 `~/Downloads`；Windows 是 `%USERPROFILE%\Downloads`。如果系统把下载目录重定向到 OneDrive，请用 `--out` 指定实际目录。

**重启后聊天记录还在吗？**

不在。lanfly 只使用内存保存本次运行的状态，关闭终端即清空；接收到的文件不受影响。

## 开发

```sh
pnpm install    # 同时安装本地 Bun
pnpm build:native # macOS 开发：编译 Rust 原生组件（需 Rust 工具链）
pnpm dev        # Vite 8080 + 本地服务 8087
pnpm build      # 构建 dist/cli.js 和 dist/public
pnpm start      # 运行构建产物
pnpm test       # 单元 + 双实例集成测试
```

构建和开发脚本是 TypeScript，由 Bun 执行；发布到 npm 的 `lanfly` 包仍使用 Node 运行。更多实现细节可以直接看 `packages/`。

键鼠实现位于 `native/`（Rust/Neon/Quartz）和 `packages/server/src/input/`。本地开发先构建 `native/index.node`；正式包使用 `lanfly-input-darwin-arm64` / `lanfly-input-darwin-x64` 可选依赖。`pnpm build` 仅构建 JS 和 WebUI，不要求在其他系统上编译 Rust。

GitHub Actions 对两个 macOS 架构编译、检查并测试原生模块；JS/WebUI 检查通过后，发布事件依次发布两个原生包和主包。需为三个包配置 npm trusted publishing。发布新版本前运行 `npm version patch`（或指定版本），版本钩子会同步平台包、Cargo 和锁文件中的版本。当前仓库版本若已经发布，需先递增版本再发布包含此功能的新版本。

`pnpm test` 包含使用模拟原生层的双端加密连接测试，不会监听或注入真实键鼠；`cargo test --manifest-path native/Cargo.toml --locked` 检查原生边界逻辑。真实设备验收仍需两台已授权的单屏 Mac，覆盖四个方向切换、修饰键与鼠标释放、滚动、断网、紧急停止及显示器热插拔。
